## 1. Executive Summary

This security audit covers Phases 0 through 8 of the IELTS Learning Management System (LMS) backend. The platform provides IELTS exam preparation, exercise snapshotting, deterministic auto-grading, student deadline management, extension requests, penalties, background BullMQ job scheduling, and notification delivery.

### Overall Posture: **PRODUCTION READY**

All identified Critical, High, and Medium security issues have been mitigated and verified via automated regression and E2E suites against live MongoDB replica sets (`rs0`) and Redis instances.

## 3. Deep-Dive Audits & Remediations

### 3.1 Authentication & Token Store (`AuthModule`)
- **Argon2id Hashing:** Password hashing uses Argon2id with 64MB memory cost, 3 iterations, and 4 parallelism lanes (`argon2.argon2id`).
- **Account Enumeration Prevention:** Both non-existent email and wrong password throw generic `401 Unauthorized: 'Invalid credentials'`.
- **Refresh Token Lifecycle:**
  - Token structure: `${tokenId}.${rawSecret}`.
  - Stored in Redis: `auth:refresh:${tokenId}` with JSON payload `{ userId, tokenHash, family }`.
  - Expiration: Native Redis TTL matching `jwt.refreshExpiresIn` (`7d` default).
  - Atomic Rotation: Atomic Lua script reads and deletes the key in a single step (`GET` + `DEL`). Any replay attempt immediately receives `401 Unauthorized`.
  - Logout: Revokes the token immediately via `DEL auth:refresh:${tokenId}`.
  - Unit Test Resiliency: Gracefully falls back to an in-memory TTL map if Redis is not connected during unit test execution.

### 3.2 Authorization & Role-Based Access Control (`RolesGuard`)
- **Admin:** Full CRUD access to users, courses, exercises, assignments, audit logs, and jobs health.
- **Teacher:**
  - Can only view, update, and manage courses explicitly assigned to them (`teacherId === actor._id`).
  - Cannot approve extension requests for other teachers' courses.
  - Can view student submissions and exercise answer keys for assigned courses.
- **Student:**
  - Can only view assignments and enrollments belonging to them.
  - Cannot access user administration (`/users`), audit logs (`/audit-logs`), or queue management (`/jobs`).
  - Cannot view exercise answers before achieving a PASS score (>= 70%).

### 3.3 Data Integrity & Concurrency Controls
- **16 MongoDB Collections Audited:**
  1. `users` (Unique: `email`)
  2. `courses` (Unique: `code`)
  3. `enrollments` (Unique: `{ courseId, studentId, status: 'active' }`, Partial: `{ courseId, type: 'one_to_one', status: 'active' }`)
  4. `lessons` (Index: `{ courseId, startTime }`)
  5. `exercises` (Indexes: `{ title, type, status }`, `{ status }`)
  6. `assignments` (Indexes: `{ courseId, status }`, `{ deadlineAt, status }`)
  7. `student_assignments` (Unique: `{ assignmentId, studentId }`)
  8. `submissions` (Unique: `{ assignmentId, studentId, attemptNo }`)
  9. `translation_submissions` (Indexes: `{ studentAssignmentId, studentId }`)
  10. `extension_requests` (Indexes: `{ studentId, requestMonthVn }`, `{ studentAssignmentId, status }`)
  11. `penalty_transactions` (Unique Partial: `{ idempotencyKey }`)
  12. `notifications` (Indexes: `{ userId, isRead, createdAt }`)
  13. `email_deliveries` (Unique Partial: `{ idempotencyKey }`, `{ status, createdAt }`)
  14. `audit_logs` (Indexes: `{ entity, entityId }`, `{ actorId, createdAt }`)
  15. `student_profiles` (Unique: `{ userId }`)
  16. `teacher_profiles` (Unique: `{ userId }`)
- **Controlled Index Initialization:** In production (`NODE_ENV === 'production'`), automatic schema index rebuilding on bootstrap is disabled. Controlled index migrations are executed via `npm run init:indexes`.

### 3.4 Background Workers & Outbox Pattern
- **BullMQ Workers:**
  - `EmailProcessor`: Concurrency 5, 3 exponential backoff attempts, delivery status recording.
  - `DeadlineProcessor`: Concurrency 1, single-worker mutex preventing race conditions on deadline checks.
  - `DeadlineScheduler`: Repeatable overdue check every 60 seconds with worker restart recovery.
- **Durable Transactional Outbox:**
  - When an event occurs (e.g., assignment published, course enrolled, extension reviewed), an `EmailDelivery` record with `status: QUEUED` is persisted to MongoDB inside the business operation.
  - If Redis is available, it is immediately enqueued with deterministic `jobId: delivery.idempotencyKey`.
  - If Redis is temporarily offline, the record remains `QUEUED` in MongoDB and is automatically swept and enqueued by `DeadlineProcessor.sweepOutbox()` upon reconnection.

## 4. Operational Readiness & Observability
- **Liveness Probe (`/api/v1/health/live`):** Verifies Node.js process responsiveness and heap memory below configurable threshold (`HEALTH_HEAP_THRESHOLD_MB`, default 768MB).
- **Readiness Probe (`/api/v1/health/ready`):** Validates live connectivity to MongoDB replica set and Redis.
- **Queue Metrics (`/api/v1/jobs/health`):** Secured Admin-only endpoint reporting waiting, active, completed, failed, and delayed job counts.
- **Request Tracing:** All incoming HTTP requests are stamped with `X-Correlation-Id`, which is propagated through response headers and included in error envelopes and server logs.
